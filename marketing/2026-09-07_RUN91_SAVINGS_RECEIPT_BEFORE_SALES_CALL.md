# RUN91 — Savings Receipt Before Sales Call

## Customer Truth
A modeled savings calculator can help a buyer form a hypothesis, but it is not realized savings. A qualified enterprise pilot should start with one bounded execution boundary, evidence of the current baseline, a finite decision window, and a buyer-defined receipt that would justify a second workflow.

## Creative Strategy
**Hook:** Define the savings receipt before the sales call.

Do not ask the buyer to trust an annualized calculator output. Ask them to identify one API, MCP, model, SaaS, or service workflow; define which traffic belongs inside the pilot; state what baseline invoices or execution logs are available; and name the before/after evidence they would require before expanding.

**CTA:** Record one bounded savings pilot request after the evidence boundary is defined.
